# looot docs

> Search, price and run data APIs from one account, with the CLI, the MCP server or the REST API. Setup for every agent client, the plugin, every MCP tool, jobs and fallback, money, errors, recipes and the API reference.

## Docs

- [Introduction](https://docs.looot.ai/): looot is one catalog of paid APIs behind one token and one prepaid balance. Search, inspect the price, run a job, and pay for what completed.
- [FAQ](https://docs.looot.ai/faq): Short answers about looot accounts, tokens, jobs, fallback, prices, failed runs, connecting agents, missing providers and docs made for agents.
- [Support](https://docs.looot.ai/support): How to get help with looot: what to quote, where to ask, and how to request a missing provider.

## Get started

- [What is looot](https://docs.looot.ai/get-started/what-is-looot): looot is one catalog of paid provider APIs behind one token, one prepaid balance and one run contract, reachable from the web, the CLI or MCP.
- [Quickstart, web](https://docs.looot.ai/get-started/quickstart-web): Sign up at looot.ai, pick your organization, top up your balance, browse the catalog and connect an agent from the Connect page.
- [Quickstart, CLI](https://docs.looot.ai/get-started/quickstart-cli): Install the looot CLI, sign in, top up, search the catalog and run your first job from a terminal.
- [Quickstart, MCP](https://docs.looot.ai/get-started/quickstart-mcp): Add the looot MCP server to Claude Code, sign in with the browser, check your balance, search the catalog and run a job with fallback.
- [Run your first paid job](https://docs.looot.ai/get-started/first-paid-run): Check your balance, inspect an endpoint, run a job over the CLI, MCP or REST, read the result and the receipt, and retry safely with an idempotency key.
- [Pricing basics](https://docs.looot.ai/get-started/pricing-basics): looot is prepaid, per call or per result, with $0 on failure and no subscription. Where to see a price before you run anything.
- [Install](https://docs.looot.ai/get-started/install): Install the looot CLI with npm (Node 20 or newer), check the version, and run looot doctor to confirm the setup works.
- [Sign in](https://docs.looot.ai/get-started/sign-in): Sign in with looot login, approve the code on looot.ai, see where the CLI saves your token, and sign out with looot logout, which revokes it.
- [Browse without an account](https://docs.looot.ai/get-started/browse): Search the looot catalog and read endpoint prices before signing up, with looot search, looot inspect and the public catalog API.

## Concepts

- [Jobs](https://docs.looot.ai/concepts/jobs): What a job id is, how to run one with endpointId "job:<id>", how looot picks a provider, and what each refusal means.
- [Job inputs](https://docs.looot.ai/concepts/job-inputs): The shared input names a job run accepts, how looot maps them to each provider's own fields, and the jobInputs coverage a search row shows.
- [Fallback](https://docs.looot.ai/concepts/fallback): How fallback tries the next provider of a job inside one hold, what makes it move on or stop, and what route.skipped and route.summary tell you.
- [Free first](https://docs.looot.ai/concepts/free-first): Why free rows and providers that only bill a found result are tried before paid ones, and how a guessed answer affects what a fallback walk pays.
- [Outcomes](https://docs.looot.ai/concepts/outcomes): The difference between status, outcome and outcomeReason on a run, what weak and guessed mean, and how whoseError and retryable steer a retry.
- [Normalized output](https://docs.looot.ai/concepts/normalized-output): The normalized block next to result, which jobs carry fixed field names, the email status vocabulary, and how verdict differs from outcome.
- [Served provider](https://docs.looot.ai/concepts/served-provider): The difference between endpointId and servedEndpointId/servedProviderId, route.servedBy, and what a runs_list row shows after a fallback run.
- [Receipts](https://docs.looot.ai/concepts/receipts): How to read what a run actually cost, attempt by attempt, with runs_evidence, GET /v1/runs/{id}/attempts and the exact money in route.summary.
- [Idempotency](https://docs.looot.ai/concepts/idempotency): Why every run needs an idempotencyKey, what replays and what conflicts, and how a job run's digest differs from a direct run's.
- [Access](https://docs.looot.ai/concepts/access): What access and credential mean on a catalog row, and how to tell a runnable endpoint from one that needs your own account or has no key yet.

## Wallet and money

- [Wallet and money](https://docs.looot.ai/money): How the looot prepaid balance works, what available and reserved mean, and where to top up.
- [Quotes](https://docs.looot.ai/money/quotes): How to price a run before you make it, using a search row's estimatedPrice and costPerSuccessUsd, or inspect's estimatedMaxCost.
- [Holds](https://docs.looot.ai/money/holds): How a run reserves its estimated cost, settles at the actual charge, releases what is left, and what reconciliation_pending means for the hold.
- [What's free](https://docs.looot.ai/money/free-and-failures): Which tool calls never cost anything, which refusals happen before any hold, and when a billed "not found" answer is still charged.
- [Cost cap](https://docs.looot.ai/money/cost-cap): How fallback.maxCostUsd bounds a route's hold, what over_cost_cap and route_capped mean, and the single-provider caveat to know before you rely on it.
- [Settlement ceiling](https://docs.looot.ai/money/settlement-ceiling): The 3x rule that bounds how far a charge can rise above the estimate, when it applies, and why a multi-provider route never goes above its hold.
- [Receipts](https://docs.looot.ai/money/receipts): Where to find the exact charge for a run: actualCost, route.summary, runs_evidence and your ledger.
- [Top up](https://docs.looot.ai/money/top-up): How to add credit to a workspace, from the dashboard or with the top_up tool, and what the rate limits and error reasons mean.

## MCP tools

- [MCP tools](https://docs.looot.ai/mcp-tools): The 15 tools the looot MCP server exposes, the common error shape, and a typical agent flow through discover, run and balance.
- [search](https://docs.looot.ai/mcp-tools/search): Free catalog search. Describe a job in plain words or pass filters and get back endpoints to inspect and run.
- [search_catalog](https://docs.looot.ai/mcp-tools/search-catalog): Ranked full-text catalog search with job expansion, stats and access states, up to 200 rows a page.
- [catalog_overview](https://docs.looot.ai/mcp-tools/catalog-overview): Free tool for what the catalog covers, as categories, platforms and jobs, with counts and cheapest prices at every level.
- [discover](https://docs.looot.ai/mcp-tools/discover): Free lexical search over up to 5 eligible endpoints, scored by relevance, evidence, availability, price and freshness.
- [discover_smart](https://docs.looot.ai/mcp-tools/discover-smart): Paid tool that judges a shortlist against a plain-English use case with one small AI call, for jobs a lexical search cannot name.
- [inspect](https://docs.looot.ai/mcp-tools/inspect): Free tool that returns an endpoint's exact input/output schema, price formula, estimated max cost and a ready-to-send run template.
- [run](https://docs.looot.ai/mcp-tools/run): Run an endpoint, a job by id, or a workflow, spending prepaid credit with idempotent retries and optional fallback across providers.
- [runs_get](https://docs.looot.ai/mcp-tools/runs-get): Free tool to get one run's looot status, result and cost once settled, separate from the provider's own response status.
- [runs_list](https://docs.looot.ai/mcp-tools/runs-list): Free, cursor-paginated run history for a workspace, filtered by status or job, with bounded summary rows by default.
- [runs_cancel](https://docs.looot.ai/mcp-tools/runs-cancel): Cancel a queued or running run, same as POST /v1/runs/{id}/cancel. Already-settled runs come back unchanged.
- [runs_evidence](https://docs.looot.ai/mcp-tools/runs-evidence): Free tool for every attempt made for a run, with status, latency, receipt id and cost, as a receipt trail.
- [balance](https://docs.looot.ai/mcp-tools/balance): Free tool for a workspace's available and reserved balance, plus the top-up link and its minimum.
- [top_up](https://docs.looot.ai/mcp-tools/top-up): Get a Stripe Checkout link to add prepaid credit to this workspace. The agent never enters card details.
- [media_link](https://docs.looot.ai/mcp-tools/media-link): Get a short-lived download link for a file a run produced (audio, image, video, PDF, or a large text or CSV answer).
- [capability_request](https://docs.looot.ai/mcp-tools/capability-request): Ask for a provider or job the catalog does not cover yet, same as POST /v1/capability-requests.
- [my_tools](https://docs.looot.ai/mcp-tools/my-tools): Free tool listing the tenant tools this workspace may run, and whether each is callable right now.

- [Look up a social profile](https://docs.looot.ai/guides/social-profiles): Get a LinkedIn, TikTok or Instagram profile through looot, with the right input field for each network.
- [Find a phone number](https://docs.looot.ai/guides/phone-lookup): Find a phone number for a person from their name and company domain, or from a LinkedIn URL, through looot.
- [List the technologies a company's site runs](https://docs.looot.ai/guides/technographics): Get a company's tech stack from its domain through looot's company.technographics job.
- [Look up an IP address](https://docs.looot.ai/guides/ip-lookup): Look up an IP address's location and network through looot's ip.lookup job, and enrich it with company and person signals through ip.enrich.
- [Bring your own provider key](https://docs.looot.ai/guides/bring-your-own-key): Connect your own API key for a provider so runs on it use your account, not looot's, and know what that changes about the price.
- [Build a UI on the catalog](https://docs.looot.ai/guides/build-a-ui): The /v2 catalog routes are for building UIs that keep the whole catalog in memory, with ETag revalidation and an ids-only search. Agents and API users should use the /v1 routes.
